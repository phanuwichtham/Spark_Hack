# ปลาศาลาหุม — คู่มือสำหรับเพื่อนในทีม

ต้นแบบเว็บไซต์สำหรับโครงการ SPARK HACK Season 2 ในบริบทชุมชนบ้านศาลาหุม จังหวัดสงขลา เชื่อมการดูแลปลา การวางแผนจับ และการขายไว้ในเส้นทางเดียวกัน

**อ่านหน้านี้ก่อนลองเว็บได้เลย ไม่จำเป็นต้องเขียนโค้ดเป็น** ใช้งานผ่านเบราว์เซอร์บนคอมพิวเตอร์หรือโทรศัพท์ได้

> สถานะชุดโค้ดที่ส่งมอบ: มีหน้าเว็บ 19 หน้าและโค้ดเชื่อมฐานข้อมูลกลางแล้ว แต่ยังไม่ได้เปิด GitHub Pages หรือสร้าง Supabase ในบัญชีของทีม ค่าเริ่มต้นยังเป็นเดโมแยกแต่ละเบราว์เซอร์ ผู้ดูแลต้องตั้งค่าก่อนจึงจะเห็นข้อมูลร่วมกัน

## 1. เว็บนี้ช่วยเรื่องอะไร?

แนวคิดคือให้ผู้เลี้ยงและกลุ่มมีข้อมูลประกอบการตัดสินใจ ตั้งแต่พบสิ่งผิดปกติในกระชัง ไปจนถึงรู้ว่าปลาที่จะจับมีใครรับ และเหลือเงินให้ผู้เลี้ยงเท่าไร

- **ดูแลปลา:** บันทึกค่าน้ำและอาการ ดูสัญญาณที่ต้องตรวจเพิ่ม และติดตามงานดูแล
- **วางแผนจับ:** แยกน้ำหนักคาดการณ์ น้ำหนักที่มีผู้รับ และน้ำหนักชั่งจริง ไม่ถือว่าปลาทั้งหมดขายแล้วทันที
- **เชื่อมผู้ซื้อ:** ร้านส่งคำขอซื้อ ผู้ประสานจัดสรร และผู้เกี่ยวข้องยืนยันก่อนดำเนินการ
- **ติดตามผล:** เห็นที่มาของล็อตปลา รอบส่ง น้ำหนักรับจริง และเงินรับสุทธิตามรายการจำลอง

ทั้งหมดนี้เป็น **แนวคิดที่กำลังทดสอบ** ยังไม่ใช่หลักฐานว่าลดปลาตายหรือเพิ่มรายได้ให้ชุมชนได้จริง

## 2. เราลองเล่นเป็นใครได้บ้าง?

| บทบาทในเดโม | สิ่งที่ลองทำ | ตัวอย่างบัญชีสมมติ |
| --- | --- | --- |
| ผู้เลี้ยงปลา | ดูกระชัง บันทึกค่าน้ำ รับงานดูแล เสนอแผนจับ และดูเงินรับสุทธิ | F01 / F02 / F03 |
| ร้านอาหาร / ผู้ซื้อ | ส่งคำขอซื้อ ยืนยันออเดอร์ ตอบข้อเสนอ และบันทึกรับปลา | ร้าน A (R01) / ร้าน B (R02) / ร้าน C (R03) |
| ผู้ประสานกลุ่ม | ดูภาพรวม จัดสรรปลา ตรวจและอนุมัติแผน จัดรอบส่ง และบันทึกการเงินจำลอง | CO01 |

สลับได้จากปุ่ม **“เลือกบทบาททดลอง”** บริเวณบัญชีด้านบน บนมือถือแตะปุ่มบัญชีเพื่อเลือก

**บัญชีล็อกอินกับบทบาทเดโมเป็นคนละอย่าง:** ถ้าใช้ฐานข้อมูลกลาง ให้ล็อกอินด้วยบัญชีของตัวเองก่อน แล้วจึงเลือกบทบาทสมมติเพื่อทดลอง บทบาทเดโมไม่ได้เป็นระบบกำหนดสิทธิ์ผู้ซื้อหรือผู้เลี้ยงจริง

## 3. เปิดใช้งานยังไง?

### ถ้าผู้ดูแลแชร์ลิงก์เว็บไซต์ให้แล้ว

1. เปิด **ลิงก์เว็บไซต์ GitHub Pages** ที่ผู้ดูแลส่งให้ ไม่ใช่ลิงก์หน้ารายการไฟล์โค้ดบน GitHub
2. ถ้ามีหน้าเข้าสู่ระบบ ให้ใช้บัญชีที่ผู้ดูแลเพิ่มให้ ไม่ใช่รหัสผ่าน GitHub และไม่ใช่รหัสผ่านฐานข้อมูล
3. เลือกบทบาทที่อยากลอง แล้วเข้าหน้า **“ภาพรวม”** หรือ **“วิธีใช้ / สาธิต”**
4. หากใช้ข้อมูลร่วมกับเพื่อน ให้กด **“โหลดข้อมูลล่าสุด”** ก่อนทำรายการต่อจากเพื่อน

หากยังไม่มีลิงก์ออนไลน์ ให้ผู้ดูแลทำตาม [คู่มือนำเว็บขึ้น GitHub และตั้งค่าฐานข้อมูล](DEPLOY_GITHUB_DATABASE_TH.md) ก่อน เพื่อนที่เพียงทดลองใช้งานไม่ต้องสร้าง Supabase หรือแก้โค้ดเอง

### ถ้ามีแค่ไฟล์ ZIP และอยากลองบนคอม

แตก ZIP แล้วเปิด Terminal ในโฟลเดอร์ที่มี `index.html` จากนั้นใช้ Python ที่ติดตั้งในเครื่อง:

```bash
python3 -m http.server 8000
```

บน Windows หากคำสั่งข้างบนไม่พบ Python ให้ใช้ `py -m http.server 8000` แล้วเปิด **http://localhost:8000** ในเบราว์เซอร์ ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

ไม่แนะนำดับเบิลคลิก HTML แบบ `file://` เพราะการเก็บข้อมูลข้ามหน้าอาจไม่ต่อเนื่อง และลิงก์ `localhost` นี้ไม่ใช่ลิงก์ที่เพื่อนเปิดจากเครื่องอื่นได้

## 4. ข้อมูลของเรากับเพื่อนจะเห็นตรงกันไหม?

| โหมด | ข้อมูลอยู่ที่ไหน | สิ่งที่ต้องรู้ |
| --- | --- | --- |
| เดโมในเครื่อง — ค่าเริ่มต้น | เบราว์เซอร์แต่ละเครื่อง | เพื่อนสร้างออเดอร์แล้วเครื่องเราจะไม่เห็น เหมาะกับลองคนเดียว |
| ฐานข้อมูลกลาง — ต้องตั้งค่าก่อน | Supabase ของทีม | สมาชิกที่ได้รับสิทธิ์ใช้ข้อมูลธุรกิจร่วมกัน มีแถบ **“ฐานข้อมูลกลาง”** บนหน้าเว็บ |

ในโหมดฐานข้อมูลกลาง:

- บทบาทที่เลือกและร่างค่าน้ำ/คำสั่งซื้อยังแยกกันในแต่ละแท็บ ไม่เปลี่ยนบทบาทให้เพื่อนตามเรา
- เว็บตรวจว่ามีข้อมูลใหม่ประมาณทุก 12 วินาทีขณะเปิดหน้าอยู่ แล้วแจ้งให้กดโหลดล่าสุด ไม่รีเฟรชทับฟอร์มอัตโนมัติ
- ถ้าขึ้นว่า **“ข้อมูลกลางเปลี่ยนแล้ว”** ให้โหลดล่าสุด ตรวจรายการ แล้วค่อยทำต่อ เพื่อไม่เขียนทับของเพื่อน
- **อย่ากดเริ่มสถานการณ์ใหม่หรือรีเซ็ตโดยไม่บอกทีม** เพราะจะเปลี่ยนข้อมูลกลางของทุกคน เส้นทางปกติต้องใช้บัญชีผู้ดูแลทีม
- ร่างยังอยู่เมื่อโหลดหน้าใหม่ในแท็บเดิม แต่ไม่รับประกันว่าจะอยู่หลังปิดแท็บหรือออกจากระบบ ข้อมูลธุรกิจที่บันทึกสำเร็จแล้วอยู่ในฐานข้อมูลกลาง

## 5. ลองครั้งแรกในประมาณ 5 นาที

แนะนำเริ่มจากเส้นทาง **ส่งคำขอซื้อ → ผู้ประสานเห็นออเดอร์** ก่อน ไม่ต้องทำธุรกรรมทั้งหมดในครั้งเดียว

1. เลือกบทบาท **ร้าน A / R01** แล้วเข้าเมนู **“สั่งปลา”**
2. เลือก **ปลาเก๋าดอกแดง • ไซซ์จาน** กดถัดไป กรอกจำนวน **5 กก.** พร้อมวันและช่วงเวลารับ
3. ตรวจจุดรับ แล้วกด **“ส่งคำขอซื้อ”** เว็บควรเปิดรายละเอียดออเดอร์ใหม่และแสดงขอซื้อ 5 กก.
4. สลับเป็น **ผู้ประสาน / CO01** แล้วเข้าเมนู **“ออเดอร์”** เพื่อตรวจว่าคำขออยู่ในรายการ
5. ถ้าทดลองคนละเครื่องในโหมดฐานข้อมูลกลาง ให้เพื่อนที่เป็นผู้ประสานกด **“โหลดข้อมูลล่าสุด”** แล้วเทียบเลขออเดอร์ให้ตรงกัน

คำขอซื้อยังไม่แปลว่าขายสำเร็จ ยังไม่หักปลามีชีวิต และยังไม่สร้างยอดขาย ต้องผ่านการจัดสรร การยืนยัน และขั้นตอนถัดไปก่อน

กรณีทำขั้นตอนนี้จบแล้ว ให้ลองอีกสองเรื่อง:

- **ดูแลปลา:** เลือกผู้เลี้ยง F01 → กระชัง C03 → บันทึกค่าน้ำและอาการ → ดูผล → สร้างและติดตามงานดูแล
- **เดินเส้นทางจนจบ:** ทำตาม [คู่มือสถานการณ์สาธิต](DEMO_GUIDE_TH.md) ซึ่งมีทั้งการขายปกติและการจัดการกรณีพบความเสี่ยง

หากปริมาณพร้อมเสนอขายเปลี่ยนจากเดิม ให้ตรวจข้อมูลปัจจุบันหรือนัดผู้ดูแลเริ่มชุดสาธิตใหม่ร่วมกัน อย่ารีเซ็ตข้อมูลกลางเองเพียงเพื่อให้ตัวเลขตรงตัวอย่าง

## 6. เส้นทางเต็มที่เราอยากทดสอบ

**บันทึกข้อมูลกระชัง → ประเมินความเสี่ยง → งานดูแล → แผนจับ → เชื่อมผู้ซื้อและจัดสรร → ชั่งจริงและสร้างล็อต → ส่งมอบ → เงินรับสุทธิ**

ตัวอย่างในคู่มือสาธิต:

- **ขายปกติ:** ขายรวม 50 กก. ราคา 340 บาท/กก. ยอดขาย 17,000 บาท หักค่าแพ็ก ขนส่ง และบริหารตามเดโมรวม 1,000 บาท เหลือ 16,000 บาท **ก่อนหักต้นทุนเลี้ยง** และไม่เท่ากับจ่ายเงินแล้ว
- **พบความเสี่ยง C03:** วางแผนจับ 50 กก. แต่ชั่งจริง 47 กก. แบ่งส่งร้าน 30 กก. และพักเย็น 17 กก. ส่วนพักเย็นยังเป็นสต็อก ไม่ใช่ยอดขาย และการขายไม่ได้ปิดงานดูแลโดยอัตโนมัติ
- **ข้อมูลไม่ครบ C04:** ไม่มีค่า DO ต้องบอกว่ายังประเมินออกซิเจนไม่ได้ ไม่ตีความค่าว่างเป็นศูนย์หรือประกาศว่าปลาปลอดภัย

## 7. อยากให้เพื่อนช่วยดูอะไร?

- เข้าเว็บครั้งแรกแล้วเข้าใจไหมว่าควรเริ่มจากตรงไหน?
- แต่ละบทบาทเห็นเมนูที่จำเป็น และรู้ไหมว่าขั้นต่อไปใครต้องทำ?
- แยกคำขอซื้อ ปริมาณจัดสรร น้ำหนักชั่งจริง และน้ำหนักรับจริงได้ชัดไหม?
- คำแนะนำเรื่องค่าน้ำ/ความเสี่ยงทำให้เข้าใจผิดว่าเป็นการวินิจฉัยหรือรับรองความปลอดภัยหรือเปล่า?
- ยอดขาย เงินรับสุทธิ เงินเก็บแล้ว และเงินจ่ายแล้วสับสนกันไหม?
- บนมือถือมีข้อความล้น ปุ่มกดยาก หรือฟอร์มที่กรอกไม่สะดวกไหม?
- ถ้าใช้ฐานข้อมูลกลาง เห็นรายการของเพื่อนหลังโหลดล่าสุดไหม และมีกรณีข้อมูลทับกันหรือไม่?

ถ้าพบบั๊ก ส่งข้อมูลนี้กลับมาในกลุ่มทีมได้เลย โดยไม่แนบรหัสผ่านหรือ token:

```text
หน้าที่พบปัญหา:
มือถือ/คอม + เบราว์เซอร์:
โหมดเดโมในเครื่อง/ฐานข้อมูลกลาง:
บทบาทที่เลือก:
ขั้นตอนที่กดก่อนเกิดปัญหา:
สิ่งที่คาดว่าจะเกิด:
สิ่งที่เกิดจริง/ข้อความแจ้งเตือน:
เลขออเดอร์หรือกระชังที่เกี่ยวข้อง:
ภาพหน้าจอ (ปิดข้อมูลส่วนตัวก่อน):
```

## 8. ข้อจำกัดที่ต้องเข้าใจก่อนนำเสนอ

- ทุกชื่อ ข้อมูลปลา ออเดอร์ และยอดเงินเป็นข้อมูลสมมติ ภาพประกอบเป็นภาพสร้าง ไม่ใช่ภาพยืนยันสถานที่จริง
- ไม่ได้เชื่อมเซนเซอร์ ส่งข้อความหาร้านจริง รับชำระเงิน โอนเงิน หรือควบคุมอุปกรณ์ในฟาร์ม
- ผลประเมินเป็นกฎสาธิตเพื่อชี้ว่าต้องตรวจอะไรเพิ่ม ไม่ใช่การวินิจฉัยโรคหรือการรับรองว่าปลาปลอดภัยสำหรับอาหาร
- บางรายการใช้เวลาสาธิตที่หยุดไว้ตามชุดข้อมูล ไม่ใช่เวลาจริงที่เดินต่อเอง
- ฐานข้อมูลกลางรุ่นนี้ออกแบบให้ **สมาชิกทีมที่ไว้ใจกัน** ทดลองร่วมกัน สมาชิกอ่านและแก้ข้อมูลธุรกิจร่วมกันได้ ยังไม่แยกสิทธิ์รายฟาร์มหรือรายผู้ซื้อสำหรับใช้งานจริง
- โค้ดเชื่อมฐานข้อมูลผ่านการทดสอบด้วยเครือข่ายจำลอง แต่ยังต้องทดสอบ Supabase จริงและสองอุปกรณ์หลังผู้ดูแลตั้งค่า
- อย่าใส่ข้อมูลส่วนบุคคล ข้อมูลฟาร์มจริง หรือรหัสผ่านลงในข้อมูลเดโม และห้าม commit secret key / service_role / token ขึ้น GitHub

เมื่อต้องตรวจโค้ด ใช้คำสั่งจากโฟลเดอร์เว็บ:

```bash
node tests/run-node.js
node tests/cloud-test.js
python3 tests/check-files.py
```

**เป้าหมายของการทดลองรอบนี้:** ให้ทีมช่วยกันดูว่าเส้นทางใช้งานเข้าใจง่ายและเชื่อมกันจริงหรือไม่ แล้วนำข้อสังเกตไปปรับต้นแบบและตรวจสอบกับผู้ใช้งานจริงต่อ ไม่ใช่สรุปว่าโครงการสร้างผลกระทบได้แล้วจากเดโมเพียงอย่างเดียว
